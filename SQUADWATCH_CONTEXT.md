# Squad Watch: project context (living document)

Edit this file whenever a decision or behaviour changes. Keep it short; details live in the code and README.
Related: `WATCHLIST_CONTEXT.md` (the watchlist tool and its JSON export).

## What this is
Three tools for running Guild Wars 2 raids, all single-purpose and personal:
1. **gw2-watchlist.html**: personal blocklist / bad-players / trusted list (see WATCHLIST_CONTEXT.md).
2. **raid_squad_composer.html**: builds squads from Discord reacts, syncs the watchlist, matches names against it, stores Discord IDs.
3. **Squad Watch** (this project): a standalone Nexus (Raidcore) in-game addon: a squad window with watchlist markers, subgroups, roles, change history. Needs no Unofficial Extras.

## Workflow the addon fits
Squad Attendance (separate addon) copies the squad list to the clipboard -> press **Update from clipboard** in Squad Watch. The pasted list is the truth: an account missing from it has left; a character-name change is fine. Roles and subgroups are assigned by hand in the window. **This is the owner's real, preferred flow** (compare successive pastes across the roster). The ArcDPS live-events mode is only a fallback, kept robust but not the focus.

## How Claude works on this repo (delivery)
- Claude gets the repo (or the files it needs) and returns **only the changed/new files, in the same folder structure as the repo**, as file diffs / changed files, not a whole zipped source. The owner copies them over the repo folder, commits and pushes with GitHub Desktop, then takes the DLL from the Actions run. Claude should say which files changed and keep this file updated.
- Native checks to run before delivering: `cmake -S . -B build && cmake --build build && build/test_core`, plus a syntax-only compile of `src/addon/addon.cpp` against the real `Nexus.h` and ImGui 1.80 (stub `windows.h` in `tests/stubs`).

## Decisions about getting the in-game squad (Oct 2026)
- **No dependency on Unofficial Extras** (the owner finds it less stable than Squad Attendance). Nexus relays Extras squad updates as `EV_UNOFFICIAL_EXTRAS_SQUAD_UPDATE`, which would have given account names (offline members probably included, unverified); rejected.
- **How Squad Attendance Taker gets offline members:** it reads the game's own squad data through a private reverse-engineered library (`src-re`, GW2RE: `GetSquadMembersUUIDs`, `GetDetailedInfo`). Its public repo has no license and the RE part is private, so it is **not copied or reimplemented**; reading game memory is also against ArenaNet's third-party rules and breaks on game patches.
- Considered and **passed on for now**: Squad Watch firing Squad Attendance's keybind (Nexus `InputBinds.Invoke`) so one click does "snapshot + update". Still the best option if a one-click update is wanted again. Other option: ask the Squad Attendance author for an event/shared resource or a license.

## Design choices (and why)
- **Own window, not the game's squad panel.** Addons cannot draw on the native squad UI.
- **Clipboard is the roster source.** ArcDPS live squad events (`EV_ARCDPS_SQUAD_JOIN/LEAVE`, replay on load) exist but are an opt-in option, off by default, so they cannot fight the pasted list.
- **Live mode behaviour (confirmed in game, Oct 2026):** a live leave removes/hides the player even if they came from a paste; someone leaving the squad or the instance disappears from the list; if they rejoin (even on another character, same account) their **role is kept** (roles are stored per account); a player removed with X loses the role. ArcDPS only reports players it can see, so offline members never appear, and **your own account is never reported**.
- **Live leave grace period (v0.11, `core/leaves.*`):** a live leave is not logged at once. It waits `graceSeconds` (default **15**, option slider 0-120, `config.json` `graceSeconds`); if the same account joins again in that time (any character) the leave is forgotten silently, otherwise it is logged in Changes as a `live` entry with the role the player held. Leaves less than 3 s apart form one burst and are logged together after the newest has been away for the grace period (at the latest grace + 10 s after the oldest). The roster itself still drops the player immediately; only the report is delayed.
- **Mass leave (v0.11):** a burst of 5+ leavers, or 3+ that are at least a third of the squad, is logged as one entry flagged `mass`: "N left at once (instance change?)", the roles-left line, and up to 6 names (+N more) instead of one line per player. One alert per logged batch ("Left: ..." or "N left at once").
- **No double reporting (v0.11):** when a live leave is logged it is also removed from the "who left" baseline so the next Update from clipboard does not report it again; a pending leave that an update/composer paste already reported (or whose player is back in the roster) is dropped. Undo clears pending leaves. Pending leaves are not saved across restarts.
- **My account (v0.11, `config.json` `myAccount`, options page):** in live mode only, this account (`Name.1234`) is added to the roster after live events, at load, when the option is switched on or edited, after a composer paste, and is added to the pasted list before *Update from clipboard* so a paste that leaves you out does not report you as having left. Not re-added after a self-leave event until someone joins again. Removing yourself with X sticks until the next trigger. Off in clipboard mode (the paste already contains you).
- **Identity = account name** (case-insensitive, leading `:` stripped). Character names are display/fallback only.
- **Matching is a port of the composer's** `wlCandidateVariants` / `watchlistMatch` (decorated names, `a / b`, notes in brackets, character fallback, worst severity wins). Verified identical on 9,508 names.
- **Standing colours the account name**: red blocked, yellow flagged, green trusted. No text labels in the Watchlist column; it shows tags only (role-relevant first, then pinned, max 3, "+N more"; a parent tag is hidden when its child is present).
- **Roles are editable (v0.14).** Built-in list = `RoleSet::defaults()`; the Roles tab can add, edit (name, kind, short name, icon) and remove roles, saved whole as `roles.json` (absent = defaults; *Reset roles* deletes it). Because the whole list is saved, a role added to the built-ins in a later version only appears after *Reset roles*. Ids never change after creation (assignments, prefers, need counts and the composer exchange use them); a new role's id = the composer's `slugify(label)` (`RoleSet::slug`), numbered `_2`... if taken. `dps` can be renamed but not removed (it also means "no role" in the change log, LFG text and *Set unassigned as DPS*). Removing a role unassigns its holders (and their tank mark), clears prefers and the Need count, refreshes the "who left" baseline; it is not undoable. Kind changes away from heal clear the tank marks of that role's holders. Custom roles must also exist in the composer (same name) for the exchange: an unknown role code there is skipped and reported.
- **Role icons from image files (v0.14):** icon id `file:<name>` = `<addon folder>\SquadWatch\icons\<name>`, loaded once per session through `Textures_GetOrCreateFromFile` (identifier `TEX_SQUADWATCH_ROLE_file:<name>`). The Edit popup lists built-in icons and the images in that folder; *Add image* takes a pasted path (quotes allowed), checks the extension (png/jpg/jpeg/bmp/tga/gif) and size (4 MB), and copies it into the folder under a plain ASCII name. There is no file-open dialog on purpose (a modal Windows dialog would freeze the game). Replacing an image under the same name shows the new one after a restart.
- **Roles are built in** (no roles file) - *superseded by the editable roles above; this was the v0.2-v0.13 design.* Order: Quick Heal, Alac Heal, Quick DPS, Alac DPS, DPS, VG Condi DPS, HK, Pusher, G1, Kite G2, Q1 Kite, Lamp, Mat Tank, Q2 Kite, Ranged DPS, Decima Kite. Internal ids keep old names (e.g. `qtp_pylon_kiter` = Q2 Kite) so saved data survives renames.
- **Need counter per role** (0 = no target) instead of fixed seat counts, because the required roles differ per run. OPEN shows only when need > 0.
- **LFG Roles (v0.10, Roles tab):** copies e.g. `1quickdps, dps`: every role with open seats as `<missing><shortname lower case>` (`2alacheal`), then plain `dps` (never a quantity) when roster + open seats of the other roles is under 10, or the DPS role itself has open seats. Nothing open and squad >= 10 copies nothing. Logic: `lfgRolesText` in `core/roles.cpp`. **Zero all needs** button sets every role's Need to 0.
- **Tank** is a toggle shown only on heal roles; it is a marker, nothing more. Cleared if the role stops being a heal. The composer has the tank toggle in both its views and sends `t:1` for it; *Paste from composer* keeps it only for players whose pasted role is a healer and says so in the status line ("N tanks", "N tank marks skipped"). *Copy for composer* sends `t:1` for every tank, and the composer turns the mark on in whichever view pastes it.
- **Squad table widths (v0.8):** columns are user-resizable (drag the header dividers): Player, Role, Sub, Prefers are fixed-width columns (defaults 190 / widest role capped at 175 / 55 / widest label capped at 130), Watchlist takes the rest. Dragged widths are read back from the first row (content width) after the mouse is released and kept in `config.json` (`colW`), so they survive restarts. The addon version in Nexus is now 0.8.0 so the loaded build can be told apart.
- **Squad tab columns:** Player | Role | Sub | Prefers | Watchlist | remove. Subgroups 1-10 assigned by hand; list is grouped by subgroup.
- **Simplified subgroups (v0.12, `config.json` `simpleSub`, default on, options page):** the Sub column shows small buttons `1` `2` `3`, leaving out the subgroup the player is in (two buttons for someone in 1-3; all three for no subgroup or 4+). A player not tracked before gets subgroup 1: `Roster::setDefaultSubgroup(0)` (set from the option in `applySubgroupMode`) applies to new members from *Update from clipboard*, composer paste (players without a seat) and live join / My account without a subgroup. Existing members, manual moves and subgroups that arrive with the data (ArcDPS, composer `s`) are never touched, and the default is not stored in `squad.json`. Option off = old picker (1-10 + None) and new players start without a subgroup. Sub column default width 72 (55 with the option off).
- **Set unassigned as DPS (v0.12):** was "Assign unassigned as DPS" in the Roles tab; reworded and also a button at the top of the Squad tab (`setUnassignedDps` in addon.cpp). Same behaviour: everyone without a role gets DPS; not undoable (as before).
- **Copying:** click a name -> account without `.1234`. *Copy by role* uses the composer format `Name1, Name2 - Role; Name3 - Role`, limited by a subgroup picker (All subs / Sub N) because the in-game chat holds **199 characters** (the status line warns above that). Roles tab: click a role row to copy that role. *Copy squad* writes `Account.1234, Character` as UTF-16 so emoji survive.
- **Composer exchange (v0.5, replace since v0.7):** Squad tab buttons *Copy for composer* / *Paste from composer*; one-line JSON `{"gw2squad":1,"members":[{a,c,r,s,t,p}]}` (`s` 1-based, `p` = Prefers, optional). Core in `src/core/exchange.*`. Paste **replaces** the squad list (no matching against the old list, so an empty or stale list is fine): each entry becomes a member (account if the name is one, else the name is kept as the character), with its subgroup, role, tank (heals only) and preferred role; roles/tanks of the old list are dropped, a preferred role is kept for a player who stays and whose paste has none, a missing character name is kept from the old list, duplicates are skipped, unknown role codes are skipped and reported. Like an update it logs who joined/left in the Changes tab, and it is undoable. The composer does the name cleaning on copy (first valid account, see COMPOSER_CONTEXT).
- **Prefers (v0.6):** per-player preferred role, a marker only (like Tank): *Prefers* column in the Squad tab (icon + label, click to pick). Stored in `assignments.json` (`prefers`), kept by *Clear all roles*, dropped when the player leaves or is removed, part of undo. Carried in the composer exchange as `p`.
- **Performance tag first (v0.9):** for a flagged/blocked player the watchlist entry's performance level (Terrible / Awful / Bad / Mediocre) is drawn first in the Watchlist column, in addition to (not counted in) the max tags.
- **Remembered layout (v0.9):** `config.json` keeps the squad table column widths (`colW`) and the window position/size (`win`; restored once per session, ignored if it would be off screen).
- **Change tracking:** baseline snapshot (roster + roles) is refreshed whenever a role is assigned and after every update. An update logs who joined and which roles left (unassigned leavers count as DPS). History keeps the last 10; click an entry to copy e.g. `2AlacDPS, 1DPS`. Character swaps are deliberately not reported. A player removed with X is still reported at the next update.
- **Undo/Redo:** 2 steps for Update, Clear list, Clear all roles. In memory only.
- **Short names in the "roles that left" text** (no spaces): QuickHeal, AlacHeal, QuickDPS, AlacDPS, DPS, VGCondiDPS, HK, Pusher, G1, KiteG2, Q1Kite, Lamp, MatTank, Q2kite, RangedDPS, DecimaKite. Placeholder choices; change in `src/core/roles.cpp` if the lfg shorthand (aheal, qheal, adps, qdps) is wanted.
- **Quick-access icon:** transparent white glyph; hotkeys are registered with `"(null)"` (= unbound) so the tooltip shows no `[(null)]`.

## Data (in `<GW2>\addons\SquadWatch\`)
`roles.json` (only once roles were changed) and the `icons\` folder (role images added by the user), plus:
`gw2-watchlist-data.json` (the watchlist's export; `watchlist.json` also accepted; reload with *Reload watchlist*), `squad.json`, `assignments.json` (roles + tanks), `snapshot.json`, `changes.json`, `config.json` (copy format, option toggles, need counts).

## Layout
- `src/core/`: portable logic, unit-tested natively: text/unicode, match, watchlist, roster, roles, history, undo. Unicode tables are generated by `tools/gen_unicode_tables.js` so lower-casing and letter checks equal JavaScript's.
- `src/addon/addon.cpp`: Windows + Nexus + ImGui 1.80 glue; `icon_png.hpp`, `role_icons.hpp` are generated (`tools/gen_icon.js`, `tools/gen_role_icons.py` from the composer's embedded icons).
- `tools/crosscheck*.js`: compare C++ against the composer's real JS.
- `.github/workflows/build.yml`: builds on `windows-latest`, runs tests, uploads `squad_watch.dll`; tag `v*` makes a release.

## Known limits / open items
- Event payload layout (`EvAgentUpdate`) is from Nexus docs; only matters if live events are enabled.
- Live mode, v0.11: the grace period, mass-leave logging and My account are unit-tested (core) and syntax-checked (glue), **not yet played in game**. Not done on purpose: an "Open roles" line, role-gap alerts (only grace period, mass leave and My account were asked for).
- Emoji/CJK names render only if Nexus's font has the glyphs.
- Role icons are 64px PNGs from the composer's `ICON_MAP` (Decima Kite's icon, key `decima`, was added in v0.13; `role_icons.hpp` was spliced by hand for it, a future `tools/gen_role_icons.py` run produces the same entry).
- Lowercasing is per character, so a word-final capital sigma differs from JS (irrelevant for account names).
